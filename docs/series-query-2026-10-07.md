# 경기 요약·상세 조회 분리 — 2026-10-07

## 구현
`matchSeries` 요약에는 팀·대회·KST 날짜/시각·점수·세트 문서 주소만 담는다. 원본 시리즈 ID와 대회로 안정적인 문서 키를 생성한다. 마지막 세트의 팀 순서를 첫 세트와 맞춘 뒤 점수를 저장한다. 기존 `matches` 상세 문서는 보존한다.

목록은 sortKey 내림차순으로 최대 10개 시리즈를 조회한다. 날짜 필터는 같은 sortKey의 범위 조회이며 별도 복합 인덱스 없이 기본 단일 필드 인덱스를 사용한다. 더 보기는 문서 스냅샷 커서로 이어 읽는다. 정확히 10개면 마지막에 빈 페이지를 한 번 읽을 수 있다. 경기를 펼칠 때 해당 시리즈의 세트들만 읽는다. 세트별 추가 지연 조회는 이번 범위 밖이다.

접었다 펼칠 때는 이미 읽은 상세 정보를 재사용하며 목록 새로고침 때 초기화한다. 필터가 바뀌면 이전 비동기 응답은 무시한다. 새 워커 저장은 상세와 요약을 같은 배치로 반영한다. 기존 5세트로 요약 2개를 생성했다. 원본 ID가 없는 기존 자료는 요약 생성에서 제외했다.

## 이전 명령
`ai-worker/venv/Scripts/python.exe ai-worker/series_summary.py`는 미리보기, `--save`는 요약 저장이다. 현재 마이그레이션은 기존 matches를 관리 환경에서 한 번 전체 조회하므로 대량 이전 시에는 별도 페이지 처리가 필요하다. 일반 사용자 목록 조회와는 다르다.

## 보안 규칙 적용 완료
기존 운영 규칙은 matches만 공개 읽기 가능해 새 matchSeries 조회가 차단되었다. 사용자가 Firebase 콘솔에서 새 규칙을 게시하여 해결했다. `firestore.rules`는 기존 규칙에 요약 get과 최대 10개 list 허용만 추가했다. 클라이언트 쓰기와 그 외 컬렉션 접근은 금지한다. 관리자 서비스 계정에 규칙 테스트 권한이 없어 운영 규칙 변경은 수행하지 않았다. 사용자 게시 후 실제 목록과 펼치기 확인을 완료했다.

## 제한
요약 목록의 제공 수는 전체 대회 경기 수가 아니다. 전체 시즌 수집·자동 실행은 아직 미구현. 병렬 수집 작업의 덮어쓰기 방지와 재개 기능도 별도 단계다. 오래된 요약을 마이그레이션에서 자동 삭제하지 않는다.

## 현재 검증
Python 21개·프론트 14개 테스트 통과, ESLint·빌드 통과. 요약에서 선수 상세 제외, 팀 전환 점수 대응, 원본 중복 거절, 목록의 날짜·개수 제한 쿼리, 지정한 세트만 조회, 누락/잘못된 세트 거절을 확인했다. 사용자 규칙 게시 후 브라우저에서 경기 요약 2개 조회, 경기 펼치기, 2세트 전환, Casting 선수의 아이템·룬·스킬 순서 표시를 확인했다. 익명 REST 조회로 10개 제한 목록과 날짜 범위 조회 성공, 없는 날짜 빈 결과, 11개 조회 거부(403)를 확인했다. 실제 자료가 2경기라 더 보기 커서의 연속 페이지는 아직 운영 데이터로 검증하지 않았다.
