# 수집 안정화 · 2026-10-07

## 개발 목적

반복 실행이 이미 저장된 경기까지 재수집하는 비용을 줄이고, 한 경기에서 실패해도 다른 경기를 저장하며, 중단 후 처음부터 시작하지 않도록 한다. 자동 예약 실행 전의 수동 운영 기반이다.

## 코드 흐름과 학습

collect.py의 discover는 등록된 대회에 속한 완료 세트 ID를 페이지 단위로 모두 탐색한다. 최근 N개 제한 없이 조회하며 기존 2,000행 안전 상한을 넘기면 실패한다. 너무 큰 범위는 날짜별로 나눈다. 탐색 단계에서 실패하면 불완전한 목록을 성공으로 저장하지 않는다.

processor는 Firestore의 같은 시리즈 원본 ID와 비교한다. ID 집합이 같고 요약도 올바르면 비싼 선수·타임라인 조회를 건너뛴다. 누락이 있거나 refresh가 지정되면 fetch_matches로 시리즈 전체를 다시 가져와 선수 10명·세트 번호 연속성·원본 ID를 검증한다. analyzer.save_documents가 상세와 요약을 같은 배치로 저장하고 다시 읽어 확인한다.

collection_job.run_job은 각 시리즈 처리 전후에 실행 파일을 기록한다. 성공은 saved 또는 skipped, 실패는 failed다. failed가 하나라도 있으면 전체 상태는 partial_failure이고 종료 코드 1이다. Ctrl+C를 받으면 interrupted를 기록하고 종료 코드 130이다. 재개 시 성공 항목은 건너뛰고 실패·미완료 항목만 시도한다. 저장은 끝났지만 결과 기록 전에 중단됐어도 재개 시 DB를 비교하여 중복 저장을 막는다.

checkpoint는 임시 파일을 쓰고 flush/fsync 후 원본 파일과 교체한다. worker_lock은 OS 파일 잠금으로 같은 저장소의 collect.py/analyzer.py 중복 실행을 막고 프로세스 종료 시 해제된다. 잠금 파일이 남아 있어도 자동으로 다시 실행할 수 있다. 다른 컴퓨터의 작업은 잠그지 않는다.

새 문서는 원본 GameId 해시로 결정적인 ID를 만든다. 재실행 시 날짜·팀 진영이 달라져도 같은 원본 경기의 주소가 바뀌지 않는다. 기존 문서는 sourceGameId 조회로 찾아 ID를 유지한다. 같은 ID가 여러 문서에 있으면 저장을 중단하며 요청 내 중복 ID와 문서·원본 개수 차이도 거부한다.

## 기록과 한계

실행 기록은 .collection-runs 폴더에만 저장하며 비밀 키·계정 ID·원본 API 응답은 기록하지 않는다. 오류 메시지 대신 오류 종류와 처리 단계를 기록한다. 이 기록은 로컬 파일이므로 다른 서버에서 자동 재개할 수 없다. 새 실행은 원본 목록을 새로 조회하며, 재개는 기존 목록에 있던 실패·미완료 항목만 처리한다.

기본 비교는 원본 ID와 요약이 기준이다. 원본 스탯 수정은 --refresh로 반영한다. 날짜를 지정하면 자정을 넘는 시리즈의 나머지 세트를 놓치지 않도록 전체 시리즈를 다시 조회한다. 완료 세트와 시리즈 종료 여부는 다르다. 상세 JSON 미제공은 별도 ID 목록으로 남기며 기본 경기 수집을 막지 않는다. 원본에서 사라진 세트는 자동 삭제하지 않는다.

## 검증

포스트시즌 실제 13시리즈·55세트는 모두 저장·요약 일치로 건너뛰었다. 결승 날짜를 --refresh --save로 다시 수집해 4세트 저장 후 ID·요약 대조를 통과했다. 저장 문서는 기존과 같은 61개(원본 ID 있는 60개와 과거 원본 ID 없는 1개)로 유지했다. 월즈 미리보기는 완료 기록 0개로 DB를 변경하지 않았다.

Python 35개·프론트엔드 18개 테스트를 통과했다. 테스트는 부분 실패 후 계속 처리, 실패 항목만 재개, Ctrl+C 이후 재개, 동시 실행 거부와 잠금 해제, 정확한 대회·한국 날짜 탐색, 중복 원본 거부, 이미 저장된 시리즈 건너뛰기, 요약 누락 복구, 세트 번호 누락 시 저장 거부를 검증한다. 화면 파일은 변경하지 않았다.
