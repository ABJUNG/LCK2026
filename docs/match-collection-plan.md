# 경기 수집 확장 설계

상태: 2026-09-28 당시 설계안. 2026-10-07에 목록·상세 조회 분리, 지원 대회 분류, 포스트시즌 수집, 수집 실행 기록·재개를 구현했다. 아래 현재 제약은 설계 당시 상황이며 최신 구현·검증은 [수집 안정화 기록](collection-stability-2026-10-07.md)을 참고한다. 전체 정규시즌 채우기와 자동 예약 실행은 남아 있다.

## 서비스 범위
첫 목표는 2026 LCK의 완료된 경기 전체. 이후 MSI·월즈 등 국제대회, 이전 시즌 순서로 확장한다. 대회별 원본 식별자를 확인하고 지원 목록에 명시한다. ‘모든 경기’와 ‘모든 경기의 모든 상세 기록’은 다르다. 원본에 타임라인이 없는 경기도 기본 결과를 제공하고 빌드·스킬·AI 제공 여부를 각각 표시한다.

## 현재 제약
- `fetch_matches`는 LCK·연도 문자열과 국내 팀 이름 목록으로 탐색한다. 날짜 지정 시 해당 날짜의 시리즈 전체, 날짜 없이 실행 시 최근 N개 시리즈만 수집한다. 날짜 지정 시 limit는 적용되지 않는다.
- 국제대회에 현재 팀 필터를 그대로 사용하면 해외 팀이 있는 경기를 누락한다.
- 현재 10명 선수·밴 기록 검증 실패 시 실행 전체가 실패한다. 대량 처리에서는 실패 시리즈를 별도로 남기고 정상 시리즈를 계속 처리해야 한다. 오류를 성공이나 빈 결과로 바꾸지는 않는다.
- 목록은 Firestore matches 전체 문서를 읽는다. 선수 타임라인까지 매번 내려받으므로 대량 수집보다 조회 구조 분리가 먼저다.
- 현재 API 재시도·원본 GameId 기반 갱신은 있지만 기간별 재개 지점·수집 실행 기록은 없다.

## 단계 1: 목록과 상세 조회 분리
`matchSeries`에 시리즈 ID, 대회 ID, 팀 ID, 시작 시각, 스코어, 세트 ID, 제공 범위만 저장한다. 목록은 정렬+제한+커서 방식으로 시리즈 단위 조회하고, 경기 펼치기/세트 선택 시 상세 문서를 읽는다. 세트 단위로 목록을 자르면 시리즈 일부만 표시될 수 있으므로 목록 페이지 단위는 시리즈로 한다. 선수 상세 데이터가 커지면 별도 문서로 분리한다. 문서 직렬화 크기를 기록하고 저장소 제한에 접근하면 분리한다.

필터는 대회·시즌·팀·날짜. 필요한 복합 인덱스와 공개 읽기/관리자 쓰기 규칙을 함께 관리한다. 기존 원본 ID를 보존하고 새 요약 문서를 먼저 생성·대조한 뒤 화면을 전환한다. 이전 문서를 먼저 삭제하지 않는다.

## 단계 2: 과거 경기 채우기
1. 지원 대회의 정확한 원본 ID와 일정 범위를 확인한다.
2. 일별 또는 작은 기간별로 시리즈 ID 목록을 탐색한다. 고정 기간과 안정적인 ID 정렬을 사용한다.
3. 시리즈 단위로 수집·검증·저장한다. 목록에 발견한 세트와 저장된 세트 수를 대조한다.
4. 실행 ID, 기간, 성공 ID, 실패 ID/사유, 재개 위치, 시도 횟수를 저장한다. 일부 실패 실행을 전체 성공으로 표시하지 않는다.
5. 중단 후 미완료 시리즈부터 재개하고 같은 GameId 재실행은 중복 문서를 만들지 않도록 한다. 동시 실행 잠금 또는 원본 ID 기반 결정적 문서 키도 필요하다.
6. 단일 작업자로 낮은 호출 속도부터 시작한다. 서버의 제한 응답을 존중하며 대기·상한 있는 재시도를 적용한다.

선수 상세 JSON 미제공은 경기 결과 수집 실패와 구분한다. 누락 수치를 0으로 만들지 않는다. 전 대회 수집 전, 작은 기간에서 중단/재개·중복 실행·부분 실패를 검증한다.

## 단계 3: 새 경기와 원본 수정 갱신
정기 실행 시 최근 며칠을 겹쳐 다시 조회하는 방식을 사용한다. 경기 직후 아직 입력되지 않은 기록이나 원본 수정도 반영할 수 있다. 오래된 누락 경기는 별도 재시도 큐와 주기적 대조 작업으로 보완한다. 완료 세트와 전체 시리즈 종료 여부를 구분하며, 일정/시리즈 종료 근거 없이 전체 경기 완료라고 추측하지 않는다.

## 단계 4: AI 분석 분리
데이터 수집 성공과 AI 성공을 별도 상태로 관리한다. AI 입력에 실제 쓰는 근거만 지문으로 만들고, 표시 전용 필드 변경으로 불필요하게 재분석되지 않게 한다. 근거가 바뀐 경기만 분석 대기열에 추가한다. 우선 최근 경기부터 처리하며 실행별 건수·비용 한도와 수동 재시도를 둔다. 과거 전체 경기 수집 시 AI를 한꺼번에 호출하지 않는다.

## 검증 기준
- 원본의 대상 시리즈/세트 수와 저장 건수를 대조할 수 있다.
- 반복 실행해도 문서 수가 불필요하게 늘지 않는다.
- 중단 후 이어서 실행할 수 있고 실패 항목이 확인된다.
- 목록 첫 화면에서 전체 선수 타임라인을 내려받지 않는다.
- 기록 미제공과 0을 구분한다.
- 수집 성공률, 누락 건수, 마지막 성공 시각, API 호출 수 및 AI 처리량을 관찰할 수 있다.

## 학습 순서
목록과 상세를 분리하는 이유 → 커서 페이지 조회 → 중복 없는 저장 → 재시도와 재개 → 자동 실행 순서로 구현하며 각 단계에서 실제 입력/출력과 실패 사례를 확인한다.
