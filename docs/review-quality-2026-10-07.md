# AI 분석 품질 평가 · 2026-10-07

## 무엇을 평가했나
결승 4세트의 생성된 분석을 현재 워커가 전달하는 경기 스탯·오브젝트 타임라인과 사용자 제공 1세트 관전평에 대조했다. 검토자는 Codex 에이전트이며 사용자가 직접 내용 검토를 완료한 것은 아니다. 경기 영상·원문 최신판은 대조하지 않았다.

## 평가 기준
| 기준 | 확인 방법 | 보류해야 할 설명 |
| --- | --- | --- |
| 기록 일치 | 승자·라인업·피해량·오브젝트를 현재 근거와 비교 | 다른 팀·선수·챔피언, 없는 수치 |
| 근거 범위 | 해당 문장이 인용한 F/N 근거의 내용 확인 | 종료 골드에서 경기 중 골드 변화 추론 |
| 사건 순서 | 타임라인의 팀·종류·시각 및 관전평 순서 비교 | 없는 교전 장면, 획득 순서 뒤집기 |
| 의견 구분 | N의 작성자 의견 유형·출처 표시 확인 | 관전평을 영상 검증된 사실로 취급 |
| 가독성 | 요약·밴픽·흐름의 역할과 문장 반복 확인 | 같은 내용 반복, 과도한 평가 |

판정은 기록과 일치 / 근거 부족으로 수정 / 작성자 의견으로 표시 / 영상 검토 필요로 구분한다. 숫자 점수로 정확성 비율을 주장하지 않는다.

## 실제 발견 사례
| 세트 | 기존 설명 | 문제와 근거 | 정정 방향 |
| --- | --- | --- | --- |
| 1 | 루시안 피해량·마지막 교전 해석 | 요약에 피해량 F4를 보완하고 마지막 종료에는 N5를 대응. 기존 마지막 교전 근거의 F24는 더 이른 바론 획득이었다. | 실제 내용과 관련된 근거만 연결 |
| 2 | 바론으로 골드 격차를 크게 벌림 | F21·F26은 바론 획득 시각뿐이며 시점별 골드를 제공하지 않음 | 첫·두 번째 바론 이후 포탑·억제기 파괴 기록 |
| 3 | 전 라인 우위 | F1·F6·F7은 승자·종료 스탯·피해량이며 라인전 과정을 입증하지 않음 | 드래곤·바론 확보와 룰러의 팀 내 최대 피해량 |
| 3 | 오브젝트 독식으로 성장 차이를 벌림 | 상대 드래곤·바론 0은 확인되지만 성장 차이 변화는 미제공 | 바론 이후 포탑·억제기 파괴 순서 |
| 4 | 중후반 교전 화력으로 제압 | F1·F3·F6은 종료 기록이며 실제 교전 장면을 제공하지 않음 | 바론 이후 건물 파괴와 승리 |
| 4 | 중반까지 팽팽 | F19·F20은 드래곤 획득 시각이며 경기 균형을 입증하지 않음 | 양 팀의 드래곤 획득 순서 |
| 4 | 바론 직후 파상공세 | 건물 파괴는 확인되지만 공격 장면 묘사는 미제공 | 바론 뒤 포탑·억제기 철거 사실 |

자동 검사에 걸린 근거 부족 문장은 6곳(세트별 0·1·2·3)이다. 1세트의 근거 대응 개선은 에이전트의 수동 대조에서 발견했으며 자동 검출 수에 포함하지 않았다.

## 코드와 실제 저장
- review_quality.py: 알려진 근거 부족 표현을 차단하고, 길이·정확히 같은 문장 반복은 경고한다. 관전평 예외는 문장이 인용한 N 근거에만 적용한다.
- review.py spectator-v7: 생성 지침을 좁히고 응답 저장 전에 품질 검사를 수행한다. 통과해도 qualityScreen.semanticVerification은 not_performed다.
- evaluate_saved.py: 저장된 분석을 읽기만 하는 재평가 명령. Gemini 호출·DB 수정은 없다. 현재 근거 해시·사실 목록·JSON 구조·ID도 확인한다.
- 정정은 AI를 재호출하지 않고 에이전트가 제공 근거를 대조하여 편집했다. AI 초안과 다르게 수정된 내용이라는 contentOrigin을 저장한다.
- 원래 보고서·발견 문제·검토자·검토 범위·시각을 editorialRevision에 보존했다. 저장 트랜잭션에서 원래 보고서와 경기 근거가 바뀌면 덮어쓰지 않는다.
- humanReviewStatus는 not_reviewed로 유지한다. 사용자가 검토했거나 영상까지 검증했다는 의미로 바꾸지 않았다.

실제 오류·근거·정정본은 [평가 사례 JSON](evaluations/finals-review-2026-10-07.json)에 보존했다. 1세트 관전평 자료와 가공 문장은 해당 문서 기여자, 사용자 제공 2026-10-07, CC BY-NC-SA 2.0 KR 조건으로 구분하며 JSON에 원문 URL·출처 메타데이터가 포함된다. 경기 기록은 Leaguepedia Cargo·V5 JSON에서 정리한 자료다.

## 다시 실행
저장소 루트에서:
```powershell
ai-worker/venv/Scripts/python.exe ai-worker/evaluate_saved.py --series-id "LCK/2026 Season/Season Playoffs_Finals_1"
ai-worker/venv/Scripts/python.exe -m unittest discover -s ai-worker/tests
```

정정 전: 3세트가 needs_correction, 근거 부족 6곳. 정정 후: 4세트 모두 screened, 해당 규칙의 문제 0곳. screened는 제한된 검사 통과이며 내용 정확성 검증 완료가 아니다. Python 67개 테스트 통과. 브라우저 도구의 URL 접근 정책으로 화면 자동 검증은 수행하지 못했으며, 실제 DB 재조회와 평가 명령으로 정정본 저장을 확인했다. 화면에서는 목록 새로고침으로 불러올 수 있다. 실제 오류 사례·정정본, 관전평 범위 예외, 오래된 근거, 생성 응답 거부를 검증했다.

## 사용자와 함께 배울 점
바론 획득 시각만 있는 근거에서 골드 격차를 알 수 있을까? 알 수 없다. 바론 뒤 포탑이 파괴됐다고 해서 어떤 교전으로 이겼는지 알 수 있을까? 교전 기록 또는 관전평이 필요하다. AI가 붙인 근거 ID가 존재하는지와 그 근거가 문장을 뒷받침하는지는 다른 검사다.

## 한계와 다음 과제
