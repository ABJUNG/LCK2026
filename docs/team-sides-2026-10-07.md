# 세트별 블루·레드 진영 표시 수정 · 2026-10-07

## 원인

groupMatches가 시리즈 첫 세트의 팀 순서에 맞춰 모든 세트를 정렬했다. MatchCard는 왼쪽을 파랑, 오른쪽을 빨강으로 칠했다. 시리즈 점수는 읽기 쉬웠지만 실제 진영이 바뀌는 세트에서도 같은 팀이 파란색으로 표시되었다.

## 수정

Leaguepedia V5 경기 JSON에서 10명 참가자의 챔피언 조합을 각 팀과 대조한다. teamId 100은 BLUE, 200은 RED로 teamSides에 저장한다. Team1/Team2의 배열 위치만으로 추측하지 않는다. 새 수집에도 동일 처리를 적용한다.

groupMatches는 시리즈 점수를 위해 기존 팀 순서를 유지하며 teamSides도 선수·밴·점수·오브젝트와 함께 정렬한다. MatchCard의 orientBySide는 선택한 세트의 실제 진영에 맞춰 왼쪽 블루, 오른쪽 레드로 배치한다. 시리즈 스코어 옆에는 해당 점수의 팀 이름을 명시한다. 선수 상세는 전환 후의 팀·선수를 참조한다. 진영 자료가 없으면 팀 순서를 유지하고 회색과 ‘진영 미확인’으로 표시한다.

## 기존 데이터 보완

backfill_team_sides.py --save로 저장된 60세트의 원본 JSON·챔피언·KDA를 모두 확인한 후 teamSides 필드만 추가했다. 선수 기록·빌드·AI 리포트는 덮어쓰지 않았다. 공개 정보만 남긴 검증 결과는 team-sides-verification-2026-10-07.json에 있다. 기본 실행은 검증 미리보기이며, 최대 200세트로 제한한다.

## 검증

Python 25개·프론트엔드 18개 테스트와 린트를 통과했다. 기본 빌드는 기존 Windows 구성 로더 문제로 실패했으며, npm run build -- --configLoader native로 빌드를 통과했다. 기존 번들 크기 경고는 남아 있다. 회귀 테스트는 진영 변경 때 선수·밴·오브젝트·점수가 함께 이동하고 원본 데이터와 시리즈 점수를 보존하는지 확인한다.

실제 화면에서 결승 1세트는 Gen.G 블루·한화 레드, 2세트는 한화 블루·Gen.G 레드로 바뀌는 것을 확인했다. 2세트 오른쪽 Kiin 클릭 시 Gen.G·Varus 선수 상세가 연결됨을 확인했다. 저장 후 다시 읽어 원본 ID가 있는 60세트 모두 진영 필드가 있는 것을 확인했다. 별도로 남아 있는 원본 ID 없는 과거 문서 1개는 진영을 추측하지 않고 그대로 보존했다.
